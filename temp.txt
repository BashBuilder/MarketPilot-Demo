GROUND RULES
- Backend output models are the source of truth (root AGENTS.md section 4).
- Do not edit backend files to make the frontend parse; fix the frontend schemas and consumers.
- If a fix requires changing the shared API contract, stop and confirm. Update section 2 in BOTH
  backend/agent.md and frontend/agent.md in the same commit.
- Backend models use extra="forbid" and are frozen; they emit exactly the fields listed here.
- Backend text fields often have minimum lengths. The frontend `text` helper is min(1), so it
  accepts backend output; tighten only where you want contract parity.

PRIORITY 1 — backend output cannot currently pass the frontend schema

1) AudienceResearch shape
Backend emits:
  {
    "segments": [{"name": "...", "description": "..."}],
    "pain_points": ["..."],
    "messaging_angles": ["..."]
  }
Frontend expects:
  {
    "summary": "...",                        // backend never emits
    "segments": [{"name", "description", "pain_points", "messaging_angles"}]
  }
Problems:
  - `summary` is required by the frontend but absent from the backend.
  - `pain_points` and `messaging_angles` are top-level in the backend, nested per segment
    in the frontend.
Fix in package.ts:
  export const audienceSegment = z.object({
    name: text,
    description: text,
  });

  export const audienceResearch = z.object({
    segments: z.array(audienceSegment).min(1),
    pain_points: z.array(text).min(1),
    messaging_angles: z.array(text).min(1),
  });
Then update any component/card that reads research.summary, segment.pain_points or
segment.messaging_angles.

2) CreativeDirection has a required `concept`
Backend emits: image_prompts, video_prompts, style_guide, composition, negative_prompts.
Frontend also requires `concept`, which the backend never emits.
Fix: remove `concept` from the schema and from consumers. If the product needs a concept
field, add it to the backend model first and update section 2 of both guides.
Also make `video_prompts` required with min(1), because the backend always emits a non-empty list:
  video_prompts: z.array(text).min(1),
and make negative_prompts non-empty:
  negative_prompts: z.array(text).min(1),

3) Compliance item field names and types
Backend emits: {"check": "...", "passed": true|false, "reason": "..."}
Frontend expects: {"claim": "...", "status": "pass"|"fail", "reason": "...", "policy": "..."}
Problems:
  - `check` vs `claim`
  - boolean `passed` vs enum `status`
  - `policy` is frontend-only
  - top-level `passed` on complianceReport is frontend-only
Fix in package.ts:
  export const complianceItem = z.object({
    check: text,
    passed: z.boolean(),
    reason: text,
  });

  export const complianceReport = z.object({
    items: z.array(complianceItem).min(1),
  });
Then update all UI that reads item.claim, item.status, item.policy or report.passed.

4) CreativeScore structure
Backend emits five named dimension objects plus total:
  {
    "brief_alignment": {"score": 8, "justification": "..."},
    "audience_fit": {...},
    "copy_quality": {...},
    "visual_quality": {...},
    "compliance_risk": {...},
    "total": 76.0
  }
Frontend expects:
  {"dimensions": [{"dimension": "...", "score": ..., "justification": "..."}], "total": ..., "recommendation": "..."}
Problems:
  - named fields vs array with a `dimension` discriminator
  - frontend allows fewer than five dimensions and duplicates; backend requires exactly five
  - `recommendation` is frontend-only
Fix in package.ts:
  export const scoreDimension = z.object({
    score: z.number().min(0).max(10),
    justification: z.string().min(5).max(200),
  });

  export const creativeScore = z.object({
    brief_alignment: scoreDimension,
    audience_fit: scoreDimension,
    copy_quality: scoreDimension,
    visual_quality: scoreDimension,
    compliance_risk: scoreDimension,
    total: z.number().min(0).max(100),
  });
Then refactor the score chart and any code that maps over `dimensions` or reads `recommendation`.

PRIORITY 2 — package wrapper mismatch (needs a contract decision first)

Backend models serialize as wrapper objects:
  AdCopySet   -> {"variants": [CopyVariant, ...]}
  AssetSet    -> {"assets": [Asset, ...]}
Section 2 says the package has `copy` (variants per channel) and `assets` (uri, checksum, ...)
and the frontend package schema currently expects plain arrays:
  copy: z.array(copyVariant).min(1)
  assets: z.array(asset)
If the API serializes WorkflowState directly, backend payloads will be:
  {"copy": {"variants": [...]}, "assets": {"assets": [...]}}
and the frontend package parse will fail.

Recommended resolution: keep section 2's external package shape as plain arrays and have the
backend package serializer unwrap `AdCopySet.variants` and `AssetSet.assets`. That is a backend
change; raise it with the backend agent rather than changing frontend schemas alone.

If the backend confirms wrappers are the final API shape, change package.ts to:
  copy: z.object({ variants: z.array(copyVariant).min(1) }),
  assets: z.object({ assets: z.array(asset).min(1) }),
and update every consumer of package.copy / package.assets.

PRIORITY 3 — frontend schemas are looser than backend (accepted now, tighten for parity)

- CampaignBrief.constraints: backend requires min 1, frontend allows empty.
- ComplianceReport.items: backend requires min 1, frontend allows empty.
- CreativeDirection.negative_prompts: backend requires min 1, frontend allows empty.
- AssetSet.assets: backend requires min 1, frontend allows empty.
- Asset.seed: backend int >= 0, frontend allows negative -> z.number().int().nonnegative().
- Asset.checksum: backend requires 64 hex chars -> z.string().regex(/^[0-9a-fA-F]{64}$/).
- Asset.uri: backend min 5 and no whitespace; frontend is text (min 1).
- ScoreDimension.justification: backend min 5, max 200, single line; frontend is text (min 1).
- Asset has four frontend-only optional fields: kind, width, height, alt_text. Backend never
  emits them. Remove them or mark them as future work; do not build UI that depends on them.
- All backend text fields have model-specific minimum lengths (for example product >= 2,
  goal/audience >= 5, tone >= 3). Frontend text is min(1). This does not break consuming
  backend output, but it will not catch backend drift.
